# Threads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add threads to Helm: approval-minted, time-bound focus topics that sit on a root memory entry and carry a timeline, todos, deadlines, reminders, and watchers. They show in a Threads page in the dashboard.

**Architecture:** Four new tables hold what has to be queried or scheduled:
- `threads`
- `thread_items`
- `thread_watchers`
- `thread_candidates`

The narrative (Goal / Past / Now / Next / Retrospective) lives in a root `memory_entries` row of type `thread`. `backend/src/services/threads.ts` owns all thread logic, and `/api/threads/*` exposes it. A new `threads` MCP service calls those routes with the gateway token, as memory does. Three tools are locked to approval in code, and their approved executors run in-process: `thread_propose`, `thread_close`, `thread_add_watcher`. A 60-second scheduler fires reminders. A 15-minute sweep turns watcher matches into candidates.

**Tech Stack:**
- Backend: Node 20, TypeScript, Fastify, Postgres via `client.execute` (the libsql-compatible wrapper in `backend/src/db/index.ts`), Vitest
- Frontend: React 18, React Query, Tailwind, lucide-react

**Spec:** `docs/superpowers/specs/2026-10-17-threads-design.md`

## Global Constraints

- Timestamps are `TEXT` columns holding ISO strings (`new Date().toISOString()`), matching every existing table.
- IDs come from `nanoid()`.
- The active-thread soft cap is `5` (`THREAD_SOFT_CAP`). It never blocks; it only appears in the approval message.
- The brief returns at most `20` events (`BRIEF_EVENT_LIMIT`).
- Reminder tick interval is `60_000` ms. Watcher sweep interval is `15 * 60_000` ms.
- Locked tools are `thread_propose`, `thread_close`, `thread_add_watcher`. They require approval even when `agent_tool_permissions` says `allow`. `block` stays `block`.
- No route accepts agent auth (`x-reins-agent-secret`) and mints, closes, or adds a watcher.
- Thread root content uses exactly these headings, in order: `## Goal`, `## Past`, `## Now`, `## Next`, `## Retrospective`.
- Error codes are `THREAD_CLOSED`, `THREAD_ROOT_PROTECTED`, `THREAD_TYPE_RESERVED`, `SCOPE_HAS_THREADS`, `WATCHER_SOURCE_NOT_GRANTED`, `SUCCESSOR_INVALID`.
- Stamp before send: every reminder stamp is written in an `UPDATE … WHERE <stamp> IS NULL RETURNING` *before* delivery. This is the `trial-reminders.ts` rule.
- `threads` is never added to `ADMIN_COMPATIBLE_SERVICES`.
- Tests run against mocks or localhost only. Telegram tests use the dev bot. Nothing touches `agenthelm-core` or `app.helm.mom`.
- Every commit message ends with:

## Review Focus

These inputs or conditions are implied by the spec but no feature test naturally hits them. Each line has a pinning test in the task named.

1. **An agent granted only scope A asks for a thread in scope B by id.** Expect 404, not 403. An id is not an authorization boundary. *(Task 4: `GET /api/threads/:id returns 404 for a thread outside the caller's scopes`)*
2. **A Gmail watcher sweep where the agent's `gmail_search` was switched to `require_approval` after the watcher was approved.** The sweep must not raise an approval. It suspends the watcher. *(Task 10: `suspends a watcher when the read tool is no longer allow`)*
3. **The approval for `thread_propose` expires while the backend restarts.** The in-memory executor is lost. The approval must not later mint through some other path. *(Task 7: `an agent-secret POST /api/threads is refused`)*
4. **A reminder whose `remind_at` is in the past at creation**, for example an agent logging "remind me about this" with yesterday's date. It must fire once on the next tick, not be silently dropped, and not fire again. *(Task 9: `fires an item created with a past remind_at exactly once`)*
5. **A user deletes a memory scope while threads in it are closed.** Allowed. Only non-closed threads block the delete. Closed thread rows are deleted along with the scope. *(Task 3: `allows deleting a scope whose threads are all closed`)*
